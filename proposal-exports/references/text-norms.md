# 文字与符号规范（图内文字）

> 图内文字是**对外承诺**的一部分，规范程度直接影响评审对"这伙人靠不靠谱"的判断。

## 1. 称谓层级：先定后用

中文申报材料里最常见的自相矛盾来自"课题 / 子课题 / 研究内容"混用。开工前先定一张表：

| 层级 | 例（本项目） | 谁在用 |
| --- | --- | --- |
| 上级（项目/课题） | 课题2 复杂电磁环境下高精度定位技术 | 总体组／导师 |
| 本级（本部分） | 本子课题 / 研究内容4 通感资源组网协作调度 | 我们 |
| 下一级（本部分内部） | 4-1 ~ 4-4 研究子内容 | 我们 |
| 兄弟（并列部分） | 研究内容1/2/3（同级的其他部分） | 兄弟团队 |

**规则**

1. 同一层级在一份材料里**只有一个叫法**；导师/总体组定了就跟随，不要自创。
2. 本部分自称统一（如"本子课题"），不要在同段里"本课题/本部分/本项目"乱换。
3. 引用兄弟部分时用**与上级一致的编号 + 全名**，避免歧义（"课题二"在一份稿里既可能指母课题、
   又可能指兄弟子课题——这种歧义一旦出现，改用不依赖编号的写法）。
4. 层级改动（如"课题四"→"研究内容四"）必须**全局替换**并在台账留痕。

## 2. 符号与记法禁用表

| 禁用 | 改用 | 说明 |
| --- | --- | --- |
| `↓≥10%` `↑` | `降低 ≥10%` / `提高 ≥N%` | 箭头是工程口语；与正文逐字一致 |
| `＋` 作连词 | `与` | 全角加号只用于专名：`5G-A＋毫米波` |
| `·` 作并列 | `、` | 与正文顿号一致 |
| `->` `=>` | `→`（仅连线标签/流程带） | 连词位置不要用箭头 |
| `≤10 m@1 km` | `1 km 处定位精度 ≤10 m` | "精度@距离"是自创记法 |
| `100ms` / `10km` | `100 ms` / `10 km` | 数字与单位间加半角空格 |
| `50:50`（写全时） | `固定 50:50 时频划分` | 缩写要能自解释 |
| `>>>`（正式交付图） | `说明：` 或另起小字行 | 仅当上级示例本身用 `>>>` 且要求原样时保留 |
| `~` 表示范围 | `3~8 站`（可）／`-` 连接数字（避免） | 保持一致即可 |

保留的规范符号：`≥ ≤ ＞ ＜ % ℃` 半角数字、全角括号（中文语境）、顿号、破折号 `—`。

## 3. 换行与断句

1. **换行落在词间**：`通信与感知共用同一套 / 时频、空域与功率资源` ✅；
   `…共用同一套 / 时频` ❌（把并列项拆开）。
2. 一个方框内 2~4 行为宜；超过 4 行考虑拆框或缩字。
3. 跨行**必须拆成独立 `<text>`**（各带自己的 `y`），不要用同一 `<text>` 内多 `<tspan>` 靠 `dy`；
   行尾补标点，保证某些不认 `dy` 的查看器里拼起来仍读得通。
4. 中英混排：中文与半角英文/数字之间加半角空格（`支持 5G-A 组网`）。
5. 括号：中文语境用全角 `（）`；纯英文/公式内用半角 `()`；同图统一。

## 4. 缩写与全称

- 首现给全称：`交替方向乘子法（ADMM）`、`第三代合作伙伴计划（3GPP）`；之后可单用缩写。
- 图与正文**各自独立**满足这条规则（评审可能只看图）。
- 不要在图里出现只在正文定义过的缩写而不给全称。

## 5. 图内文字的内容边界

| 应该写 | 不该写 |
| --- | --- |
| 结论性短语、方法名、交付物名、指标（带限定） | 整段论述、文献综述 |
| 与正文一致的术语 | 即兴造词、内部代号 |
| 未定项的"待定/待 XX 给定" | 猜的数值、编的单位 |
| 连线标签写"给了什么" | "相关""有关"这类空话 |

## 6. 自查清单

- [ ] 称谓只有一套，且与上级一致
- [ ] 禁用符号 0 处（`check_symbols.py`）
- [ ] 缩写首现皆有全称
- [ ] 中英数字间空格一致
- [ ] 换行不拆词、跨行拆成独立 `<text>`
- [ ] 无自造术语；未定项已标注
- [ ] **无生僻/学术腔术语**（见 §7）
- [ ] **编号已尽量换成词标签**（见 §8）

## 7. 术语：先查权威，再谈通俗化（**不要自己编术语表**）

顺序是 **① 查规范术语 → ② 用规范写法 → ③ 只有当规范词过于学术、而评审不是同行时**，
才在规范词之外补一句白话，**两个都写**，不要用自造词替换规范词。

| 权威来源 | 用途 | 怎么用 |
| --- | --- | --- |
| 全国科技名词委 [术语在线 termonline.cn](https://www.termonline.cn/about) | 中文**规范术语**（各学科已审定名词） | 逐词查；有审定名就用审定名（这是国内最权威入口） |
| ISO 704 / GB/T 15237《术语工作 原则与方法》 | 术语工作原则：一个概念一个名称、先定义后使用 | 自造概念（如"站簇"）必须给定义，且全文一义一称 |
| GB 3100~3102《量和单位》 | 量与单位的法定名称、符号、正斜体 | 指标行单位写法（km、ms、GHz、%、km/h…） |
| 目标期刊/出版社的图表规范（如各学报《表格、插图、量和单位使用规范》） | 图表编号、图注位置、量与单位标注 | 报送/投稿前对齐对方要求 |
| 已有 skill（[opum-ai/diagram-skills](https://github.com/opum-ai/diagram-skills#1)、[artifact-diagramming](https://github.com/Piebald-AI/claude-code-system-prompts/blob/9c962047d0b423e162102c222d2b4cd4a3ac7f1e/system-prompts/skill-artifact-diagramming.md#1)、[excalidraw-skill](https://github.com/aref-vc/excalidraw-skill#1)） | 图形语言、命名与检查清单 | **先看别人怎么做**，再决定要不要自建 |

**只有权威来源查不到时**才写"项目内约定"，并显式标注"（项目内约定，非规范术语）"。

> 曾经的做法是"自己整理一张生僻词改法表"——那是重复造轮子。规范术语查 [术语在线](https://www.termonline.cn/about)，
> 单位查 GB 3100~3102，图表格式看目标刊物规范，本 skill 只保留**查不到时才用**的项目内约定。

### 7.1 本项目内约定（示例，非规范术语，随项目走）

| 词 | 项目内写法 | 备注 |
| --- | --- | --- |
| 二者**不可公度** | 二者**量纲不可比** | "公度"为度量学/哲学词，评审易卡壳；工程语境用"量纲不可比" |
| 折中**边界** | 折中**曲线** / **可行域** | "边界"多义 |
| **保证**达到 / **彻底**解决 | 补限定条件，或改"支撑/力争" | 与"不画大饼"条款同源 |


## 8. 编号与标签：优先用词，不用裸编号

- **能用一个词说清的，不要用编号**。例：研究内容行的表头写「组网建模」「站簇配对」「任务调度」
  「跨频段协作」，比写「4-1」「4-2」信息量大得多，读者也不必回头查编号含义。
- 必须编号时（上级已给定编号体系），**全图只能一种体系**（中文一/二/三 或 阿拉伯 1/2/3），
  与上级编号的对照表放**结构说明**里，不放在图上。
- 同一列上下两行指同一条内容时，**用同一个词标签**，不要一行写编号、另一行写别的。

## 9. 竖排文字：横向也要居中（`rotate(-90)` 的 0.30em 偏移）

`transform="rotate(-90 x y)"` 只把**基线**转到 x 上，字形并不以 x 为中心：
基线上方 ≈0.85em、下方 ≈0.25em，故**字形盒中心比锚点左偏 0.30em**，
竖排标题会"垂直居中、横向偏左"，色块越窄越明显（24px 字号偏 7px）。

```
锚点 x = 色块中心 x + 0.30 × 字号
（fs=17 → +5.1；fs=24 → +7.2）
```

两种做法：

| 做法 | 写法 | 取舍 |
| --- | --- | --- |
| 坐标补偿 | `x="65.2" transform="rotate(-90 65.2 500)"`（色块中心 58） | ✅ 各查看器与 PPT 导入一致，推荐 |
| 基线属性 | `dominant-baseline="central"` | 语义正确，但部分渲染器/转换工具支持不一 |

> 这是 SVG 文本旋转的已知问题（[Text rotation from centre not accurate](https://stackoverflow.com/questions/32020510/text-rotation-from-centre-not-accurate?rq=4#1)），
> 不是本 skill 的独创；`check_overlap.py` 的旋转文字包围盒用的就是同一套 0.85/0.25em 模型。



## 10. 禁止"为塞进框宽而截断词句"

框不够宽时，**改框或改字号，不许砍词**。砍出来的"电报体"一眼就假，评审会逐句读不顺。

| 症状 | 实际发生过的例子 | 正确做法 |
| --- | --- | --- |
| 砍虚词 | 「感知指标硬约束、代价为目标」（原话：感知指标**为**硬约束、**通信**代价为目标） | 正文 fs 14→13，可用宽度 212px 可放 16 汉字 |
| 砍动词 | 「须在非凸域**求折中**」（原话：求**取**折中） | 同上，或换行成两句 |
| 砍名词 | 「4.9 GHz **远距**、毫米波**高精度**」（原话：远距**离探测**、高精度**定位**） | 缩成「4.9 GHz 远距探测、毫米波定位」 |
| 丢标点 | 「调整**时频功率**」（原话：时频、功率） | 补顿号；宁可换行 |
| 生造动词 | 「按拓扑与贡献度**定**站簇与配对」 | 「按拓扑与各站贡献度**选**站簇与配对」 |

**自检方法**：`audit_text.py --md` 导出文字清单，逐条问三句——
① 这句话在正文里能找到出处吗？② 读出来是完整句子吗（主谓宾齐）？③ 有没有被砍掉的字（虚词/量词/顿号）？

> 实测：一次返工里 10 条格内文字被砍成电报体（问题一~四、研究内容四格），
> 根因是"按能塞下的字数改词"。把 fs 从 14 降到 13 后，原话全部补回，宽度仍有富余。


## 11. 竖排文字：SVG 用 rotate，不要照搬 PPT 的 eaVert

模板（PPT）里竖排用 `vert="eaVert"`（CJK 竖排、字正立），**但 SVG 没有可靠等价物**：

| 写法 | 渲染器表现 | 结论 |
| --- | --- | --- |
| `writing-mode="vertical-rl"` | Chrome/Edge 无头正常，**部分查看器与 PPT 导入不认 → 字横过来** | ❌ 实测踩坑，勿用 |
| `transform="rotate(-90 x y)"` + 锚点右移 `0.30em` | 各处一致 | ✅ 采用（偏移见 §9） |

**教训**：跟模板要落在**当前载体的能力边界**内——模板是 PPT（eaVert 原生支持），我们是 SVG（只能 rotate）。
照搬属性名而不看载体，会做出"在我这儿好好的、在别人那儿是坏的"的图。同类问题还有：
PPT 的块箭头（SVG 要用 `<marker>`）、PPT 默认圆角、PPT 主题色继承（SVG 必须写死 hex）。
