# 样式令牌（配色 / 字体 / 尺寸）

> 目的：同一份材料里的多张图**看起来像一套**。改配色只改这里，不要在图里即兴调色。

## 1. 调色板

| 角色 | 描边 | 填充 | 用在哪 |
| --- | --- | --- | --- |
| 主色 | `#2F6FB0` | `#E8F1FA` | 本部分核心框、子内容框、主要箭头 |
| 层次带标题 | `#4A7EBB`（底） | 白字 | 技术路线图的带标题、矩阵图的竖排标签块 |
| 深色标题条 | `#2F6FB0`（底） | 白字 | 图顶部标题条 |
| 强调 | `#E8A33D` | `#FDF3E3` | 支撑产出框、验证带、产出类图元 |
| 弱化（兄弟项） | `#9AA5B1` | `#F2F4F7` | 兄弟课题/子课题、非本部分内容 |
| 正文 | — | — | `#1F2937` |
| 次要文本/小字注 | — | — | `#4B5563` |

规则：**一图不超过主色 + 强调 + 弱化三组**；同一语义在所有图里用同一组色。

## 2. 字体与字号

```text
font-family="Microsoft YaHei, PingFang SC, Source Han Sans SC, SimHei, sans-serif"
```

| 用途 | 字号 | 字重 |
| --- | --- | --- |
| 图主标题 | 30 | bold |
| 上级课题/通栏标题 | 24 | bold |
| 带标题 / 竖排标签 | 17~20 | bold |
| 模块标题 | 17~18 | bold（同色系深色） |
| 模块说明行 | 15 | normal（`#4B5563`） |
| 正文/条目 | 15~17 | normal |
| 小字注（协作关系、说明、图注） | 12~13 | normal（`#4B5563`） |
| 连线浮动标签 | 13~14 | normal（`#4B5563`） |

字号只在这几档里选，**不要出现 14.5 或 16.5 这种即兴值**。

## 3. 形状与线

| 元素 | 规范 |
| --- | --- |
| 圆角 `rx` | 方框 8~10；核心框 12；小标签 3 |
| 描边宽度 | 普通 2；核心框 2.5；细线/分隔线 1.5 |
| 箭头 | 每张图**自己定义** `<marker>`，`markerUnits="userSpaceOnUse"`；主箭头与细箭头各一个 |
| 连线 | 折线用 `<polyline>` + `stroke-linejoin="round"`；禁止用手绘 `<path>` 画直角折线 |
| 虚线 | 仅在表达"约束/可选"时用（`stroke-dasharray="6 4"`），且同图同义 |
| 小示意 | 只用 `rect`/`circle`/`line`/`polyline` 组合，颜色取主色系，不引入新色 |

## 4. 版面与安全边距

```text
画布      1600×900（16:9）或 1200×1000（矩阵图）
外边距    40（画布四周）
标题条    高 54，居中
通栏条    高 60~70（含 2 行小字时）
框内边距  ≥12px（四边都要留）
框间距    ≥20px（同类并列框）；≥6px（上下相邻的条目框，配合框高调整）
```

## 5. 起手模板

`assets/template.svg` 已内置：调色板常量注释、两个 marker、标题条 + 通栏 + 三列模块骨架 + 图注位置。
拷出来改文案与坐标即可，**不要**从空白文件开始画。

## 6. 导入 PPT 的注意事项

- 保持形状类别收敛、坐标取整：便于在 PPT 里按同坐标用原生形状重画（真正"可编辑"）。
- SVG 直接插入 PPT 是**图片**，不能改文字：要么按本规范在 PPT 里重画，要么用转换工具转成形状。
- 若最终交付 PPT：把 `Microsoft YaHei` 之外的字体全部去掉，避免他人机器上字形跳变。
- 导出 PNG 汇报时用 2 倍尺寸（3200×1800），投影/截图才不糊。

## 间距约定（框与框）

| 档位 | 值 | 用在哪 |
| --- | --- | --- |
| **S** | **12px** | 同级并列框之间（同一组内的兄弟框，如四条子内容框） |
| **G** | **24px** | 组与组之间 / 框与通栏 / 框与产出框 / 左列兄弟框 |
| **T** | **32px** | 内容区与底部指标通栏之间 |

实测事故：一张图里同时存在 6px、8px、18px、20px、24px 五种间距——并列框挤成 6px，
与其它框的关系又各不相同，看起来"没设计过"。**先定档位，再摆框**；摆完跑
`python scripts/check_spacing.py 图.svg --scale 12,24,32` 核对，不在档位上的会被标出。

例外必须写进结构说明（如"产出框与底部通栏间距 8px，版心贴底"），不要默默留一个数。


## 单元格内垂直节奏（表中框里的文字）

| 元素 | 相对框顶 | 说明 |
| --- | --- | --- |
| 表头基线 | **+46** | 表头字号 15 |
| 表头分隔线 | **+58** | 表头 +12，长 = 框宽 30%~80% |
| 正文首行 | **+84** | 表头 +38（分隔线 +26） |
| 正文行距（同段换行） | **24** | 与字号无关地固定，便于多框对齐 |
| 条目间距（要点之间） | **48** | = 2×行距，视觉上明显分组 |
| 注释小字行 | **24** | 与正文行距一致 |

实测事故：同一张图里"表头→正文"出现 38 与 60 两种、行距出现 24 / 26 / 42 三种——
框与框之间对不齐，读者会感到"没排过版"。

自检：`python scripts/check_spacing.py 图.svg --text-scale 24,38,48`
（输出"单元格内文字间距"分布，不在档位上的逐条标出）。


## 图文适配（框的大小与文字量要匹配）

框不是"格子"，是**内容的容器**：图文不匹配，读者第一眼就觉得"没做完"。

| 症状 | 判据 | 改法 |
| --- | --- | --- |
| **框大文字少** | 通栏里文字只占一侧、另一侧大片留白（或段落块宽 < 通栏宽 60%） | ① 横向**等分块 + 居中分隔线**（同一图里所有通栏共用这套语言）；② 字号上一档（17→19）；③ 内容确实不够就**缩框高** |
| 框小文字挤 | 行距 < 1.2×字号，或文字贴边 <12px | 缩字号或扩框 |
| 行高与内容不匹配 | 单行文字的行却给了 140px 框高 | 行高按内容定；整图行高由"最高的一行 + 行间距"反推 |

**先补内容，再动版式**（顺序不能反）：

1. **内容不够 → 回正文/技术方案取原话补足**，写进图里并把出处记进结构说明。
   这是唯一正确的"填满"方式：图上的每句话都应能在文档里找到出处。
2. **禁止为排版拆句**：一句话被硬拆成左右两块、或把一个语义单元拆成两格，属**形式主义**——
   读者会看出"这是为了填框"。等分块只用于**内容本身就是并列项**的情形（如"实验验证"三格）。
3. 内容确实只有一句话、补不出东西 → **缩小框高**（让框服从内容），不要放大字号硬撑。
4. 版式兜底：单块左对齐（缩进 24）；内容本身并列时才用等分 + 居中分隔线
   （分隔线长 = 通栏高 − 2×20，1.5px、opacity .45）；段内行距 32（fs17）/ 36（fs19）；块垂直居中。

> 反面教材（真实返工）：目标需求通栏 1012×190 只有左侧 4 行小字，第一次改成
> "左右两块 + 分隔线"——**被指出是形式主义**：那句话本是一句完整表述，被硬拆成两半。
> 正确做法是从正文取四句原话（低空监管需求 → 现有手段局限 → 资源同源同池 → 本子课题做什么）
> 补成四行左对齐叙述，框自然就满了，且每句都可追溯。
