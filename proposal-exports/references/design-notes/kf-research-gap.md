# kf research.md 的缺口（R3）

> 只提建议，不改 `kf-personal-development`。用户确认后再决定是否同步。

## 结论

`kf-personal-development/references/research.md` 对「事实、工具、方案选型」够用；对「视觉、版式、
审美」这类没有唯一正确答案的方案，缺一套可复现的比较协议。

## 够用的部分

- **问题卡**：要解决什么、现状、约束、已知失败、完成判据，直接适用于画图/做页片。
- **来源优先级**：一手优先，二手交叉验证，三手只找线索，适用。
- **证据卡**：来源、主张、条件、本机验证、结论，适用；视觉方案也能记「在哪台机器、什么版本、
  什么画布」。
- **停止条件**：四问能挡住无限检索，适用。
- **读论文公式**：原生载体、结构树、混用上报，适用。

## 不够的部分

视觉方案的「好坏」不能只靠读文档判断，必须同内容对照：

1. 同一份内容、同一画布，换引擎或版式分别渲染；
2. 固定评分维度：比例与留白、中文排版、信息层级、可检查性；
3. 记录安装成本、失败模式、改版成本；
4. 截图和评分表一起归档，结论要能复现。

`research.md` 现在没有「同内容对照」「评分维度」「失败模式」这三步，容易变成看几篇文章就下结论。

## 补丁草案（给 kf 的 research.md 加一节）

```markdown
## 视觉方案调研

适用：画图引擎、版式、配色、图表类型这类没有唯一答案的选择。

1. 固定输入：同一份内容、同一画布尺寸，不许换文案；
2. 候选各渲染一版，记录安装成本、失败模式、改版成本；
3. 四维评分：比例与留白、中文排版、信息层级、可检查性；
4. 截图与评分表归档，结论写「为什么选它、什么情况下不选」；
5. 停止条件：候选覆盖主要路线，且结论能解释现有失败案例。
```

## 建议

- 这条补丁对 `proposal-exports`、`paper-experiment` 都适用，不只画图；
- 是否合并进 kf，由用户决定；本 skill 先在 `diagram-engine-decision.md` 里按这个协议做 R2。
